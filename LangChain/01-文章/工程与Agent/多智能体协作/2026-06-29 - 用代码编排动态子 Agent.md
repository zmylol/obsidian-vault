## 摘要

Deep Agents 的动态子 Agent 让模型编写 JavaScript 编排脚本，在轻量解释器中通过循环、分支和并发分派子任务，中间结果留在运行环境中。这样可以明确遍历已知输入清单，并组合并行汇总、独立核验等多阶段工作，而不必由主模型逐次发起调用。使用时需要子 Agent 和代码解释器，文中的 SDK 接法是另行安装并启用 QuickJS 中间件。文章展示六种模式及示例轨迹，没有给出统一性能对照；派发覆盖也不等于发现范围完整或子任务结论正确。

## 重点图文解读

### 把派发范围写成明确循环

对已列出的文档页或文件，循环比临时逐项决定更容易检查覆盖情况；子任务的语义正确性仍需另外验证。

### 先展开处理，再汇总结果

批量独立任务可并行执行后合并；文章用目录代码检查说明这一形状。

## 适用条件与局限

代码能约束已知清单的派发，不保证发现阶段完整，也不保证子 Agent 的结论正确；并发量与资源成本仍需控制。

## 怎样理解与应用（AI 解读）

先把待处理文章固定成清单，再记录每个 URL 的成功、失败与重试状态。批量完成后核对清单差集，比依赖“已全部处理”的自然语言回复更可靠。
