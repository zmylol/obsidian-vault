## 摘要

Deep Agents 0.5 新增异步子 Agent：派发后立即返回任务 ID，主 Agent 可继续对话或处理其他工作，再查询结果、补充指令或取消任务。子 Agent 保留自己的线程上下文，运行端采用 Agent Protocol，也支持省略远程地址后在同一进程内通信。文件读取同时扩展到 PDF、音频和视频等格式，仍使用 read_file 接口，但能否理解相应内容取决于底层模型。文章说明的是当时版本的功能与协议选择，没有提供异步化的定量性能对照。

## 重点图文解读

### 把任务生命周期显式化

开始、检查、更新、取消和列出任务成为独立操作，耗时工作不必阻塞主 Agent 的整段交互。

### 远程任务保留自己的线程

方案使用 Agent Protocol 的线程和运行模型，后续指令可以沿着已有上下文继续处理。

### 文件支持仍受模型约束

读取工具可按扩展名传递 PDF、音频和视频等内容；底层模型必须支持相应输入类型。

已核对正文：包含代码和任务工具表，没有嵌入关键图片或视频；以文字解释任务生命周期。

## 适用条件与局限

这是当时版本的协议选择，文中对其他协议的比较具有时效性；异步化还需要处理结果收集、取消与失败状态。

## 怎样理解与应用（AI 解读）

把资料抓取设计成有明确状态的任务，用户可以继续提出新要求，完成后再统一验收。检查“已派发”和“已完成”是否在记录中清楚区分。
