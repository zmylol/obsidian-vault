## 摘要

LangChain 发布的 Eval Engineering Skill 帮助编码 Agent 读取仓库结构和可用调用记录，提出值得测试的能力，再通过用户反馈逐步确定任务与评分标准。产物采用 Harbor 格式，把任务说明、运行环境和评分器放在一起，便于固定条件比较不同 Agent 配置。团队在文档问答 Agent 上试用了这一流程，并发现评分器也需要反复检查，避免无关引用或虚假完成声明骗过评分。文章没有给出定量提升，强调的是与人协作设计和复核评估，而非一次生成就自动可信。

## 重点图文解读

### 从仓库和记录提出待测能力

先映射提示、工具、服务和实际调用，再由用户选定方向；收费或会写生产数据的依赖可在测试中模拟。

### 评分器本身也要被检查

同时查看 Agent 的动作与评分器的依据，防止靠大量无关引用、虚假完成声明或暴露的答案拿分。

### 将任务、环境与评分器一起冻结

Harbor 任务封装说明、环境和验证逻辑；同一评估可比较不同提示、模型和工具，并根据审阅反馈修改。

## 怎样理解与应用（AI 解读）

**AI 解读：**若评分只要求“包含引用”，可以故意提交含许多无关引用的答案，检查评分器能否识别取巧；这是验证评分标准的练习。
