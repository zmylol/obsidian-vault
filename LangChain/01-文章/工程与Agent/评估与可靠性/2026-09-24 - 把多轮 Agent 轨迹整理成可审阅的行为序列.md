# 把多轮 Agent 轨迹整理成可审阅的行为序列

## 摘要

LangSmith 新增 Trajectories，把同一会话中主 Agent、子 Agent、用户和工具的消息按首次出现顺序汇总，每条只保留一次，帮助读者追踪行为过程。审阅者可由关键步骤跳回完整调用轨迹，工程团队也能对整段会话运行在线评估、送人工标注，或保存为微调数据。这种视图省去嵌套执行结构，具体时序和重试仍需查看原始 trace。发布时仅美国区域所有套餐可用，文中没有给出调试效率提升的量化验证。

## 重点文字解读

### 从执行树提取行为顺序

LangSmith 的 run 组成 trace，多轮 trace 组成 thread；Trajectory 从这些记录提取消息和动作，消除重复历史。它保留可读的行为顺序，而底层调用记录仍承担细节核查。

### 先定位异常行为，再下钻

原文用客服会话举例：先找出重复使用旧工具结果的那一轮，再查看具体输入、输出、重试和耗时。专家审核也可从这层视图进入标注队列，不必先理解整棵执行树。

### 让整段过程进入评估和数据集

在线评估可给整个会话路径评分，把低分样例送审，把高质量轨迹保存到数据集。用于后训练时，工具调用和结果与最终回答一样重要；文章没有证明自动筛选后的数据天然适合训练。

## 适用条件与局限

发布时美国区域所有套餐可用。视图是对原记录的投影，具体运行结构和重试仍应回到 trace 核对。文中调试案例是说明用途，没有量化效率实验。

## 怎样理解与应用（AI 解读）

**AI 解读：**可以先用轨迹回答“从哪一步开始偏离”，再用原 trace 验证原因；给人工审核设计字段时分开记录行为问题和执行故障。这样得到的标签也更容易回流评估。本次未接入真实流量。
