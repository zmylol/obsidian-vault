# 用生产轨迹筛选数据并验证模型微调

## 摘要

LangSmith 的 smithtune 将成功轨迹筛选、监督微调和留出数据评估连成一条流程，训练由 Fireworks 或 Baseten 托管。公司报告：简化版 Engine 在内部 IssueBench 子集上，Kimi K3 的任务分数从90升至96；代码审查内部评估中，Qwen 的 F1 从48.9%升至53.7%，模型调用减少29.8%。这些是限定任务的自测，较差的数据筛选曾让 F1 下降，不能推断普遍收益。功能处于公测，需 LangSmith 轨迹及训练提供商 API 密钥。

## 重点图文解读

### 保留每个动作当时可见的材料

轨迹不仅保存最终对话，还记录逐轮可见的工具定义。工具延迟加载时，直接导出最终消息列表会遗漏早先动作的真实条件，影响监督样本的对应关系。

### 先筛数据，再训练和比较

smithtune 组织候选轨迹审核、持久数据集和训练、验证、测试划分。用户先审查训练计划，再交给托管服务进行 LoRA 训练；留出轨迹用于比较基础模型与微调模型的动作预测。

### 限定任务中的改善与失败案例

公司在简化 Engine 的内部 IssueBench 子集报告 Kimi K3 得分90至96，同表 GPT-5.6 Sol 为87。代码审查使用 Qwen-3.8-27B，F1 为48.9%至53.7%，召回率均为40%；模型调用均值55.9至39.2。早先筛选较松的数据反而降低 F1，说明数据选择会改变结果。

## 适用条件与局限

这是公测发布及内部结果，原文未披露完整样本规模。回放评估比较记录情境下的动作，不能直接当作新环境中的端到端成功率。需要已有轨迹和训练提供商密钥；先改进运行框架、再考虑微调，是作者给出的适用顺序。

## 怎样理解与应用（AI 解读）

**AI 解读：**可先锁定一个反复出现的行为错误，分离训练样例与测试案例，并同时记录质量和调用量。若减少调用却降低目标任务召回，应单独呈现这个取舍。本次未训练模型、运行命令或复现基准。
