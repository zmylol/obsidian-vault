## 摘要

LangChain 从四款 Deep Agents 应用的开发中总结：评估应为每个任务分别规定成功条件，按需检查工具决策、最终回复或实际生成的文件等状态。单步测试用于检查下一次动作，完整运行验证最终结果，多轮测试则在每轮确认预期后继续，偏离时及时失败，避免后续输入失去意义。每个用例还应重置环境，并可回放外部请求以减少不稳定因素。这是团队的测试设计经验，没有统一效果对照；单步判断正确不能替代完整任务验收。

## 重点图文解读

### 先确定测试覆盖多长的执行

单步测试适合检查下一次工具选择；完整执行检查任务结果；多轮测试还要确认前一轮结果足以支持后续输入。

图示：单步、完整单轮与多轮交互对应不同测试范围，成本和能发现的问题也不同。

### 成功条件应落到具体产物

记住会议偏好的例子同时检查文件编辑调用、给用户的确认，以及记忆文件实际内容，避免仅凭回答宣称成功。

图示：会议偏好示例把用户要求连接到工具调用、最终回复和记忆文件，展示一次任务的多个验收位置。

### 重置环境并减少外部波动

每个测试使用干净环境；必要时录制并回放 API 交互，使失败更容易复现。
