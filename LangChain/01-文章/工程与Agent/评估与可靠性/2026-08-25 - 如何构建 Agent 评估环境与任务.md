## 摘要

LangChain 把合成 Agent 评估的构建分成两步：先用自然语言明确任务，再据此生成可运行的 Harbor 测试。跨任务共用的接口、数据结构和生成方法写入“世界规格”，单个任务的输入、环境和评分条件写入任务规格，便于人工审阅后批量生成。团队先试做少量任务，再观察实际运行轨迹和不同模型的表现，修正环境漏洞并校准难度。这是一套迭代工作方法，没有定量效果对照；领域真实性与任务难度仍需要人的判断。

## 重点图文解读

### 共享知识不等于任务规格

world spec 可保存服务 schema、mock 方法、数据生成脚本与评分规范；task spec 则明确本次环境、输入和评分条件。Markdown 规格便于人工讨论，避免直接审查大批生成代码。

### 先试少量任务再扩大

团队建议边构建首个任务边沉淀 world spec，再在新对话里生成第二、第三个任务验证其可复用性。确认后批量生成任务规格，并独立执行 Spec2Task。

### 评分与难度需要校准

Harbor 任务不只包含提示词；评分可用程序或 LLM judge，依任务决定。试跑后应读取轨迹，检查泄漏答案、错误环境和奖励漏洞；不同能力模型的结果可帮助辨别任务太易、太难或本身损坏。

## 适用条件与局限

作者明确过程并非全自动：领域代表性、用户行为与任务难度仍需人判断。生成了测试脚本并不代表评分有效，合成数据还要核验。

## 怎样理解与应用（AI 解读）

为资料整理 Agent 先准备三个验收不同的任务：来源不可读、同文异链、原文改图。分别约定笔记内容和状态文件的预期变化，再将共同约束写进 world spec。
