# 为托管 Agent 划分用户记忆、凭据与接入渠道

## 摘要

Managed Deep Agents 0.8 在托管运行框架中加入按认证用户划分的记忆和凭据、HTTP 接入、Slack 文件传输及内置网页搜索。共享记忆与用户记忆分层存放；默认只有 Slack 一对一私信允许用户记忆，群聊和 HTTP 均禁用，避免把个人上下文带入多人场景。用户凭据用于需要个人权限的服务，Agent 凭据承载共享能力。发布时仍处于测试期，Parallel 搜索免费仅限该测试期；文中没有提供独立的隔离安全验证。

## 重点文字解读

### 把运行设施放进代码项目

MDA 把框架、身份、记忆、工具与渠道组织成可部署项目。文中的销售助手例子用同一任务说明：共享流程和个人偏好进入不同作用域，工具访问也随身份变化。

图示：销售助手从私信或频道接收任务，再根据身份选择记忆、凭据和搜索能力；图示表达作用域设计。

*销售助手从私信或频道接收任务，再根据身份选择记忆、凭据和搜索能力；图示表达作用域设计。* [原图](<https://cdn.prod.website-files.com/65c81e88c254bb0f97633a71/6ab41b5374fcc495c04ca9f3_Managed%20Deep%20Agent%20flow.png>) · [文章出处](https://www.langchain.com/blog/langsmith-managed-deep-agents-whats-new)

### 用默认策略划分记忆

共享记忆位于 /memories/agent/，用户记忆位于 /memories/user/ 并绑定认证身份。默认 Slack 一对一私信允许两层；群聊、群私信与 HTTP 只允许共享层。团队可配置策略，运行时不会自动跨层复制内容。

### 凭据随调用者权限变化

连接在运行时提供命名凭据：共享搜索可使用 Agent 凭据，个人业务系统则使用用户凭据。原图还区分已授权和待授权状态；没有授权时先暂停等待同意。

图示：connections.get 按连接名和所有者取得凭据：共享、个人已授权、个人待授权分别进入不同分支。

*connections.get 按连接名和所有者取得凭据：共享、个人已授权、个人待授权分别进入不同分支。* [原图](<https://cdn.prod.website-files.com/65c81e88c254bb0f97633a71/6ab40b6111bda02b3b793351_Managed%20Deep%20Agents%20connections.png>) · [文章出处](https://www.langchain.com/blog/langsmith-managed-deep-agents-whats-new)

### 接入渠道和搜索也要带上身份

Slack 新增文件传输，HTTP 渠道允许业务系统通过 JSON webhook 接入，并由项目定义验证、解析和回复。Parallel 搜索由平台管理凭据和调用记录，测试期免费不等于长期免费。

## 适用条件与局限

记忆可用性依赖认证身份、入口和访问策略，不能把默认设置外推为任意自定义代码的保密保证。文中客户引述属于体验反馈，未提供独立安全测试；版本及免费期限均按发布日理解。

## 怎样理解与应用（AI 解读）

**AI 解读：**可用两个测试账号分别写入不同偏好，再从私信、群聊和 HTTP 请求读取，检查实际结果是否符合声明的作用域；同时测试缺少个人授权时是否停止调用。这是待验证练习，本次未创建账号或运行示例。
