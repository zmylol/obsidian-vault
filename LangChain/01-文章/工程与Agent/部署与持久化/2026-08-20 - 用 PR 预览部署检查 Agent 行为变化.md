## 摘要

LangSmith Preview Builds 为代码合并请求的源分支创建临时部署，让同事在同一运行环境里检查提示、工具和模型改动；追加提交会自动生成新版本，父部署不受这次代码更新影响。团队可按每个请求或指定标签触发，用闲置时限自动回收，并以并发上限控制同时运行的数量。预览创建时会复制父部署的凭据，因此运行环境独立不等于权限独立。2026 年 8 月发布时，该功能为公开测试版，仅面向 LangSmith Cloud 中通过 GitHub 集成连接的部署。

## 重点图文解读

### 代码评审增加可运行的对象

预览与父部署关联但运行源分支，不更新父部署。评审者可验证工具行为、失败路径和 traces；多个 PR 有各自环境，减少共用 staging 来回切分支。

### 触发与生命周期可控

Every PR 自动创建预览，Label only 则按指定标签触发。Idle TTL 与并发上限控制闲置和数量，父部署删除也会删除预览。

### 环境隔离不等于凭据隔离

创建时会复制父部署 secrets，之后保留初始集合，除非覆盖。原文建议为预览配置专用凭据，尤其是外部贡献者能触发 PR 的场景；不要假定隔离部署自动拥有独立数据权限。

## 适用条件与局限

发布时为 Public Beta，仅说明 LangSmith Cloud 的 GitHub 集成部署；视频未逐段检查，未创建真实预览环境。

## 怎样理解与应用（AI 解读）

评审一项工具修改时，把正常响应、权限不足、超时三条用例绑定到同一个 PR 预览，并确认预览使用测试资源再邀请协作者验证。
