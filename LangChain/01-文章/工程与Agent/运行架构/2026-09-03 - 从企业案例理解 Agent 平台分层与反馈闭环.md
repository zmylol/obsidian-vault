# 从企业案例理解 Agent 平台分层与反馈闭环

## 摘要

LangChain 汇总施耐德、Vodafone 和 monday.com 的实践，说明多个 Agent 上线后如何管理质量和运行边界。施耐德把生产调用记录回流到评估数据，并让各产品运行独立服务栈；Vodafone 追踪意图识别、查询和回答的全过程；monday.com 则把单一通用 Agent 重构为包含权限层、专职子 Agent、受控工具与沙箱的分层系统。作者归纳的共同经验是让失败可以定位，再把反馈用于验证。这些是选定企业的案例与自述，不能当作架构效果的对照实验。

## 重点图文解读

### 共享管理规范，产品分别部署

施耐德按产品设置跨开发和生产的 workspace；各产品使用独立 Agent Server、数据库和队列，降低共同故障影响，但增加升级协调。

### 把生产证据送回评估

生产记录经过评估信号、规则分流和专家标注，成为离线数据集；再通过实验验证下一版。

### 让多步失败可以定位

Vodafone 先识别意图，再路由到数据查询或文档检索。完整追踪可区分错误意图、SQL 和文档版本造成的问题。

### 让工具、子 Agent 和沙箱各有职责

monday.com 在模型前筛选权限与上下文，用子 Agent 专注推理、工具执行有界操作、沙箱完成代码迭代；工具按层级发现，部分工具须显式激活才加载完整定义。
