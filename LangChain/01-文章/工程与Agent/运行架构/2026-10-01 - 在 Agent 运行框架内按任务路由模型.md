# 在 Agent 运行框架内按任务路由模型

## 摘要

LangChain 为 Open SWE 编码 Agent 在运行框架内加入三档模型路由，按每个会话首条请求选定模型，并沿用至会话结束。在973个会话的内部 A/B 测试中，相比始终使用 GPT-6 Astra，每会话 LLM 成本中位数由2.61美元降至0.94美元，约降64%；合并 PR 的会话占比为29.2%对27.3%（p=0.49），未检出显著差异，不能据此证明质量等同。方案仍是概念验证，尚未覆盖会话中途换模型和对子 Agent 的统一路由。另一次以始终使用快速模型为对照的 A/B 试验因工程师反馈输出质量低而提前终止，未形成有统计意义的结果。

## 重点图文解读

### 先从真实任务看模型需求

作者先分析一周 Open SWE 运行记录，用语言模型根据会话标题和元数据划分任务。功能开发、修复错误、测试或空操作占比较大；费用和调用次数用于粗略判断复杂度，但调用多也可能是模型反复尝试造成的，不能直接当作任务难度真值。

### 将任务条件放进运行框架的路由中间件

三档分别使用 GLM-5.3-Flash（xhigh）、GPT-5.6 Sol（medium）与 GPT-6 Astra（low）。通用基准帮助选择候选，实际路由条件则依据 Open SWE 的任务、工具和领域知识制定。分类器读取首条用户请求，选定后整段会话沿用同一模型；改用 Jev 加速的是分类步骤，不能视为整个 Agent 按同样倍数提速。

图示：作者以截至2026年9月9日的 Artificial Analysis 基准选择三档模型。这里是基准每任务费用，不是后续A/B的每会话费用，也不是当前模型排名。

### 同时比较费用与任务结果

9月16日至22日的内部 A/B 测试含对照477个会话、路由496个会话。每会话 LLM 成本中位数为2.61美元对0.94美元，均值也下降约42%。主要结果指标是产生合并 PR 的会话占比，路由组29.2%、对照组27.3%，p=0.49；这个结果未检出差异，不能证明所有任务质量相等。用户评分较少，主要用于发现具体路由错误。

图示：9月16日至22日路由组与始终使用 GPT-6 Astra 的比较：LLM成本中位数0.94美元对2.61美元；PR合并占比的p=0.49不能证明质量等同。

### 快速模型与后续路线仍需验证

第二次 A/B 把始终使用快速模型作为对照，工程师很快反馈该组输出质量低，试验在一天内停止，没有形成有统计意义的结果。目前路由仍是概念验证：子 Agent 独立选模型，会话中途重新路由尚未实现，切换模型还可能损失提示缓存。受控基准、对子 Agent 统一路由等属于后续方向。

## 适用条件与局限

结果来自 LangChain 内部的 Open SWE 任务，基线为始终使用高档模型，不能据此保证其他流量也降低64%成本。PR合并只能覆盖部分任务结果，成本口径为 LLM 调用费用；图中通用基准的每任务费用与实际会话费用也不是同一指标。模型与基准截点保留原文当时条件，未另行验证今天的价格或排名；示例代码、外部基准和线上试验均未运行。

## 怎样理解与应用（AI 解读）

**AI 解读：**可先用公开或合成请求建立固定任务集，分别记录任务完成情况、人工审查结果和LLM费用，再调整各档的选择条件。分类正确率只是中间指标；最终还要检查被分到低档模型的任务是否增加返工。这是可验证的实践建议，本次未部署路由或发送测试请求。
