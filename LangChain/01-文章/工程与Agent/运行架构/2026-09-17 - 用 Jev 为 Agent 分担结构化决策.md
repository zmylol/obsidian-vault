# 用 Jev 为 Agent 分担结构化决策

## 摘要

Jev 是一种不生成文本、只返回结构化判断与概率的决策模型，可让 Agent 把部分分类任务从完整的语言模型调用中分离出来。LangChain 通过 TypeSafeClassifier 接收上下文和问题，支持选项分类、有序评分及是非判断，并提供实验性的模型路由和工具执行前风险检查中间件。它适合辅助决定调用哪个模型、是否阻止某次工具操作，开放式推理和生成仍由语言模型承担。提速降本来自供应商针对分类任务的报告，文中没有独立基准，也未证明这种检查能保证工具操作安全。

## 重点图文解读

### 把生成式回答换成程序可用的决策结果

Jev 接收状态与问题，返回类型化结果：Choice 给选项概率，Score 给有序等级的连续评分，Noul 给陈述为真的概率。一次请求可询问同一状态的多个问题；并行判断是供应商描述的执行方式，不是本次实测。

图示：同一工单分别用于团队选择、情绪程度评分和紧急性判断；0.999 是示例的紧急概率，不是模型准确率，选项概率与 confidence 也不能混为一项。

### 用分类接口接入现有上下文

langchain-typesafe 提供 TypeSafeClassifier.invoke，状态可以是文本、结构化数据或 LangChain 消息，返回分类结果而非聊天文本。 9月23日回查时，原文示例已改为向 invoke 传入包含 state 和 questions 的单个字典。示例需要 TypeSafe API 凭据；本笔记仅整理接口关系，没有安装包、读取凭据或运行调用。

### 在模型选择与工具执行前插入判断

实验性 ModelRouterMiddleware 根据最新用户消息选择模型，并在该次运行中沿用选择；概率和置信信息保留在状态里。AutoModeMiddleware 则在工具执行前检查并阻止被判为风险的调用。两者辅助运行控制，不替代开放式推理或外部权限约束。

## 适用条件与局限

性能数字来自 TypeSafe AI 的分类任务报告：最高约200倍推理速度、成本低至可比语言模型约1/400；本文未提供完整基准配置，不能当作端到端 Agent 收益。中间件处于 experimental 命名空间，风险分类也没有在本文中被证明能防住所有危险调用。

## 怎样理解与应用（AI 解读）

**AI 解读：**可以先在现有工单路由上做只读对照：记录分类概率、实际人工去向、延迟和费用。分开检查高置信误判与低置信样本，再决定阈值和人工复核范围；不要仅按概率数值高低认定判断可靠。本次未运行此实验。
