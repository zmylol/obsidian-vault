# 把混合搜索的离线建索引与在线查询分开

## 摘要

Niels Rogge 介绍 Papers with Code 如何把批量论文编码交给 Hugging Face Jobs、把校验后的产物存入 Buckets，再用 Inference Endpoints 处理在线查询和小批增量，融合关键词与向量排名。系统维护逾 11 万篇论文；在 5,000 篇试验中，256 维索引相对精确搜索的 Recall@20 为 0.9955，表与索引存储约为 1024 维版的 27%。这衡量近似检索保真度，不是语义相关性或全库效果；在线编码不可用时退回关键词搜索，且全链路须遵守同一编码约定，固定模型版本、区分查询与文档提示，并保持向量格式一致。

## 重点图文解读

### 重计算放在离线任务

批量编码由 GPU Jobs 执行，产物写入带清单与校验信息的存储；在线服务只处理查询和小规模增量。

### 用互补信号召回

关键词与向量候选经 RRF 融合，精确标题和标识符另有优先规则；语义服务超时可以退回关键词结果。

### 索引版本需要成套切换

模型修订、维度、归一化和查询格式共同构成契约，新产物验证通过后再激活，并保留回退版本。

## 适用条件与局限

文中近邻检索的 recall 数字衡量近似索引与精确向量搜索的一致性，不等同于用户认为结果相关的比例。

## 怎样理解与应用（AI 解读）

知识库的解析、摘要和索引可分别记录版本；更新失败时保留上一批可用结果，同时为精确术语保留关键词通道。
