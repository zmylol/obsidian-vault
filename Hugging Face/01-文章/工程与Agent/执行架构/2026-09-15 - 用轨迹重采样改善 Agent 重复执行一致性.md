# 用轨迹重采样改善 Agent 重复执行一致性

<!-- AUTO:BEGIN -->
[← 首页](../../../00-首页.md) · [本分类文章](../../../99-管理/收录清单.md#%E6%89%A7%E8%A1%8C%E6%9E%B6%E6%9E%84)

> [原文](https://huggingface.co/blog/ibm-research/altk-evolve-consistency) · IBM Research 机构实验文章 · 2026-09-15。作者完整名单见属性，正文已读，代码未运行、论文未精读。

## 摘要

IBM 团队在 ALTK-Evolve 中加入一致性诊断：对一条已记录轨迹的各决策点重新采样，找出容易改变选择的步骤，再生成可检索的推理时指南，无须重新调用工具或已知正确答案。在 AppWorld 的168项任务上，GPT-4.1 ReAct Agent 使用同任务轨迹生成指南后，五次新运行全部成功的任务比例从53.0%升至69.0%，平均成功率从77.4%升至81.0%；用于同一场景下其他任务变体时，五次全部成功比例也提高13个百分点。结果来自特定模型和基准，诊断每步仍需额外模型调用，不能当作生产环境稳定性保证。

## 重点图文解读

### 先区分一次成功与次次成功

平均成功率Mean@5统计五次运行的平均成绩；Pass⁵只统计五次全部成功的任务，Pass@5则只要求至少一次成功。三者回答不同问题，不能互换。原实验Agent使用temperature 0.0，作者仍观察到重复运行差异。

### 从一条轨迹定位易变决策

分析器对已记录上下文逐步重采样，每个决策点额外一次模型调用、默认请求5个补全，生成评分卡；随后把不稳定步骤提炼为指南。这项离线诊断不需要重新操作工具，也不需要正确答案，但诊断有模型调用成本。

![从轨迹诊断到检索指南的流程](../../../98-%E9%99%84%E4%BB%B6/%E5%8E%9F%E6%96%87%E9%85%8D%E5%9B%BE/altk-consistency-pipeline.png)

轨迹先经一致性分析器生成评分卡，再生成指南并存入记忆，相关指南在后续推理时检索注入。诊断使用已记录上下文，不重新执行工具或环境。 [原图](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/gdUd7l6Q8DzXCgzmchxi3.png) · [文章出处](https://huggingface.co/blog/ibm-research/altk-evolve-consistency)

### 复测时同时看两种成功率

每个任务用一条基线轨迹生成指南，再做五次新运行。GPT-4.1在AppWorld test_normal的168项任务中，Pass⁵提高16个百分点，而Mean@5提高3.6个百分点，一致性差距从24.4缩到12.0个百分点。另一个同场景任务变体上的迁移提高13个百分点，不能推广为任意任务迁移。

AppWorld test_normal 的168项任务，GPT-4.1 ReAct Agent 五次全部成功的任务比例从53.0%升至69.0%。横轴从20%起，箭头标的是百分点；不能把它看作平均成功率或无限次运行的可靠性保证。 [原图](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/E_7HyAt5BSzZy9Pj0k3Wc.png) · [文章出处](https://huggingface.co/blog/ibm-research/altk-evolve-consistency)

## 适用条件与局限

这是IBM作者在指定模型和AppWorld基准上的结果，没有独立复现。诊断不需要正确答案，不表示最终效果评测也无需判定成功。本文视觉核对四张正文图并节选流程和Pass⁵结果两张；外链两分钟演示未观看，技术报告未精读，代码未执行。

## 怎样理解与应用（AI 解读）

对同一业务请求重复运行并记录每次的工具选择，分别看平均完成率和全部成功比例。先定位经常分叉的步骤，再测试针对性提示是否同时改善两项指标；不能用统一输出代替正确输出。
