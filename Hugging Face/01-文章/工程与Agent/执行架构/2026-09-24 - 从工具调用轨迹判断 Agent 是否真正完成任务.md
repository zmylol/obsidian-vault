# 从工具调用轨迹判断 Agent 是否真正完成任务

<!-- AUTO:BEGIN -->

## 摘要

Golda Manuel 提出，评估编码 Agent 的工具使用，应把每一步可用工具、选择、参数和状态传递，与环境中实际完成的结果连起来看；任务通过不一定意味着目标产品被成功使用。她建议跨多次运行找出反复出现的障碍，修改说明或响应后，在可比条件下重跑相同任务。重复调用可能是在恢复或轮询，请求被接受也不代表处理完成，因此不能孤立追求更少调用或错误。本文提供评估方法和示例，未报告量化实验结果。

## 重点图文解读

### 从反复出现的障碍定位改进点

原文开篇设想 Agent 集成某产品失败后改用另一产品：最终任务能通过，却不能证明目标产品可被顺利使用。单次失败不足以归因；应跨运行观察同类误选、参数遗漏或响应误读，再修改工具说明、错误信息或文档，并在可比条件下重跑相同任务。

### 区分没发现工具与没有选对

每个决策点都要对照当时可用的工具和实际选择。前者缺失时应检查工具暴露与文档入口；工具已可见却被忽略时，再检查描述、区分度和任务上下文。正确选中只是后续核验的起点。

图示：工具发现与选择的判断路径

先判断所需工具是否可用且能被发现，再检查 Agent 是否选中；选对后仍须核对参数、结果和下一步动作。图中分支用于定位问题，不是成功率或性能实验。 [原图](https://cdn-uploads.huggingface.co/production/uploads/6a10aac4480cf8331c3439b6/Qjx8O4lT0iZCyoqxTMslT.png) · [文章出处](https://huggingface.co/blog/phranzia/evaluating-ai-agent-tool-use)

### 连续调用要保持任务状态

单次响应成功无法证明多步使用正确。原文要求检查参数是否对应任务、早先获得的状态是否继续使用、省略参数的默认行为是否改变结果，以及资源和权限范围是否合适。重复调用则要看状态有无变化、尝试是否推进任务；重试和轮询都有可能是必要步骤。

### 把响应解释与真实结果对齐

收到“已接受、处理中”只能说明请求进入流程，仍需后续检查。工具返回状态、后续所需标识和可恢复错误信息，可以帮助 Agent 决定下一步。最终以环境中的实际结果核验：调用数、使用过的工具数、重复次数、错误和耗时都是诊断线索，不能单独判定是否有效完成任务。

## 适用条件与局限

适合有执行轨迹和可核验目标状态的编码 Agent 工作流。原文没有给出量化收益或自动评分器，重复错误只能提示潜在使用障碍，不能证明产品就是原因。正文两张图片中保留一张技术流程图，另一张为装饰封面；指标表完整读取并概括其解释边界。未发现正文视频、iframe或canvas，未运行示例、下载模型或精读外链论文。

## 怎样理解与应用（AI 解读）

例如评估一个异步导出工具，可同时保存提交返回的任务标识、后续查询和产物检查。若 Agent 只看到“已接受”便宣称导出完成，问题在响应解释与验证环节；若正确轮询后确认产物有效，就不应因为调用更多而判为较差。这是应用示例，不是原文实验。
