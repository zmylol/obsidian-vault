# 高级工具使用的三种机制

## 摘要

Anthropic 在 2025 年 11 月为 Claude 开发平台发布三项工具使用的测试版功能：按需搜索工具、用代码组织多步调用，以及用示例说明参数的正确组合。它们分别减少预加载定义、中间结果占用和参数误用；内部复杂参数测试中，加入示例后准确率由 72% 提升到 90%。这些机制解决的瓶颈不同，搜索与代码执行也会增加步骤，因此不必每个任务都全部启用。结果来自当时的内部测试，不能直接推广到所有业务；采用时还需核对当前支持条件。

## 正文要点与配图

## 工具发现
Tool Search 让模型按需找到相关工具，不必把所有 schema 预先塞进上下文；这直接针对多服务器带来的 55K 以上 token 开销。

![Tool Search Tool 的发现流程：模型先搜索工具，再加载当前任务相关定义。](../../../98-附件/原文配图/b2c615d49c42e84c451d.png)

*图注：原图将“查找工具”和“调用工具”分成两步，相关定义只在需要时进入上下文。* [原图](https://www-cdn.anthropic.com/images/4zrzovbb/website/f359296f770706608901eadaffbff4ca0b67874c-1999x1125.png) · [文章出处](https://www.anthropic.com/engineering/advanced-tool-use)

## 程序化调用
Programmatic Tool Calling 允许模型写代码，在一次执行中循环调用工具并处理数据；适合大量行、条件筛选和跨工具组合，但执行环境的权限和失败回传要明确。

![程序化工具调用流程：模型生成代码，由执行环境批量调用工具并回传整理后的结果。](../../../98-附件/原文配图/9122c7b90e0c37dbc28d.png)

*图注：原图把代码执行放在工具服务器与模型之间，强调批量结果不必逐条回到上下文。* [原图](https://www-cdn.anthropic.com/images/4zrzovbb/website/65737d69a3290ed5c1f3c3b8dc873645a9dcc2eb-1999x1491.png) · [文章出处](https://www.anthropic.com/engineering/advanced-tool-use)

## 示例补足 schema
Tool Use Examples 用实际调用示例表达 schema 难以表达的可选参数组合和调用约定。三者组合后减少上下文、延迟与错误，但增加系统设计和调试成本。

## 怎样理解与应用（AI 解读）

把一个常用工具写出“发现描述、最小 schema、两个正确示例、一个错误示例”，再测试模型能否减少参数错误。
