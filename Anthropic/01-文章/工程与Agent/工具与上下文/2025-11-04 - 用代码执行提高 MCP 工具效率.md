# 用代码执行提高 MCP 工具效率

## 摘要

MCP 是连接智能体与外部工具的协议；当工具很多时，一次加载全部定义、让每份中间结果经过模型，会消耗大量上下文。Anthropic 提议把工具封装成代码接口，让智能体按需读取定义，并在执行环境里筛选和组合数据，只返回必要结果。文中工具发现示例的 token 用量从 15 万降到 2,000，显示了按需加载节省上下文的潜力，而非所有任务都能达到的收益。方案还需安全沙箱、资源限制与监控，必须把维护执行环境的成本一起计算。

## 两种上下文开销
直接调用数百或数千个工具，会在对话开始前装入大量 schema，也会把每次中间结果继续塞进上下文。文章用五个服务器、约 58 个工具和约 55K token 的设置说明这种固定开销如何累积。

## 代码负责机械编排
循环、条件、批量筛选和数据转换适合由代码执行，模型保留目标选择和解释结果的工作。这样减少完整推理轮次，也让大批量处理不必把所有原始结果展示给模型。

## 适用条件
代码执行环境必须有清晰的权限、错误处理和输出验证；节省 token 不等于工具结果可信，也不应把任意外部脚本直接放进生产环境。

## 怎样理解与应用（AI 解读）

为一个需要读取多条笔记的任务画出“模型决策—代码筛选—最终证据”流程，检查哪些原始结果可以安全留在执行环境内。
