## 摘要

Anthropic 研究者用 Claude Opus 4.6 连续数日开发 JAX 宇宙学求解器，以参考程序 CLASS 和测试判断进度，用持久记录保存结果、失败路线与已知限制。作者报告，模型在若干输出上达到了相对 CLASS 的亚百分比一致性，但最初设定的全范围 0.1% 精度目标不能视作已经完成。开发曾只测试单个参数点，成品仍在部分条件下精度不足，尚非生产级软件。这是作者监督下的单个案例，说明明确参照和跨会话记录有助于持续推进，不是普遍研发提速的受控证明。

## 重点文字解读

### 长任务先写清可检查的目标

案例把与 CLASS 的功能和数值比较写入项目说明，最初提出 0.1% 精度目标。目标值、参考程序与实际达到的覆盖范围必须分别记录，不能把设定目标当成完成结果。 [原文依据](https://www.anthropic.com/research/long-running-Claude)

### 进度记录要包含失败路线

作者建议保存已完成事项、误差表、已知限制及尝试失败的原因，减少新会话重复走弯路。参考实现构成测试依据，持续回归测试负责防止后续修改破坏已有结果。 [原文依据](https://www.anthropic.com/research/long-running-Claude)

### 进展曲线也暴露测试盲区

案例中精度经过多次修正逐步提升，但曾长期只测试单个参数点，也会误解物理约定。图中局部收敛不能证明整个参数空间都正确，作者明确说结果尚非生产级。 [原文依据](https://www.anthropic.com/research/long-running-Claude)
